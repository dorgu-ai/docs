## Prerequisites

<Prerequisites />

<Warning>
  **`kubectl` is not optional.** `dorgu health`, `dorgu incidents`, `dorgu remediation`, and `dorgu persona import` all shell out to `kubectl` and read your current context. Without it every cluster command fails with `kubectl not found in PATH`. Only `dorgu generate`, `dorgu init`, and `dorgu config` work without a cluster.
</Warning>

<Warning>
  **CLI v0.10.0 pairs with operator v0.9.0.** v0.10.0 refuses to patch a Deployment that Helm, ArgoCD, or Flux owns, using the `spec.workloadRef` record the operator writes. That record only exists from **operator v0.9.0**, and an absent record is treated as owned on purpose.

  So **against operator v0.8.1 or older, every remediation carrying a workload change is declined** with exit code `4`. Nothing breaks and nothing is lost: `dorgu remediation approve --no-heal` records the decision and you apply the change yourself. But if you are healing workloads today, upgrade the operator alongside the CLI.

  The reverse mismatch is the one that matters more. **CLI v0.9.0 and older do not read `workloadRef` at all**, so they will still patch an owned Deployment against a v0.9.0 operator, which is exactly what breaks the next `helm upgrade`. See [the ownership model](/ownership-model#version-coupling).
</Warning>

## Binary releases (no Go toolchain)

Every release ships pre-built archives on [GitHub Releases](https://github.com/dorgu-ai/dorgu/releases), for Linux, macOS, and Windows on both `amd64` and `arm64`.

Set `OS` to `linux` or `darwin` and `ARCH` to `amd64` or `arm64`:

```bash
OS=linux
ARCH=amd64

curl -fLO "https://github.com/dorgu-ai/dorgu/releases/latest/download/dorgu_${OS}_${ARCH}.tar.gz"
tar -xzf "dorgu_${OS}_${ARCH}.tar.gz" dorgu
chmod +x dorgu
sudo mv dorgu /usr/local/bin/
```

That URL is an unversioned alias that always resolves to the newest release, so it never needs a version bump. It was first published with **v0.9.0**; for anything older, use the pinned form below.

To pin an exact release instead:

```bash
VERSION=0.10.0
OS=linux
ARCH=amd64
ARCHIVE="dorgu_${VERSION}_${OS}_${ARCH}.tar.gz"

curl -fLO "https://github.com/dorgu-ai/dorgu/releases/download/v${VERSION}/${ARCHIVE}"
tar -xzf "$ARCHIVE" dorgu
chmod +x dorgu
sudo mv dorgu /usr/local/bin/
```

<Warning>
  Keep the `-f` in `curl -fLO`. Without it, a wrong URL writes the 404 response body to disk, `curl` still exits 0, and you end up installing a text file named after the asset you wanted.
</Warning>

The archive also contains `README.md`, `LICENSE`, and `.dorgu.yaml.example`; naming `dorgu` in the `tar` command extracts only the binary.

### Windows

Download `dorgu_windows_amd64.zip` (or `_arm64`) from the [latest release](https://github.com/dorgu-ai/dorgu/releases/latest), extract it, and put `dorgu.exe` somewhere on your `PATH`. The pinned form is `dorgu_0.10.0_windows_amd64.zip`.

### Verifying the download

Each release publishes `checksums.txt`, which covers the versioned archives:

```bash
VERSION=0.10.0
curl -fLO "https://github.com/dorgu-ai/dorgu/releases/download/v${VERSION}/checksums.txt"

# Linux
sha256sum --ignore-missing -c checksums.txt
# macOS
shasum -a 256 --ignore-missing -c checksums.txt
```

## Go install

With a Go toolchain, install the latest release:

<GoInstall />

Or pin a specific version:

```bash
go install github.com/dorgu-ai/dorgu/cmd/dorgu@v0.10.0
```

<Note>
  `v0.10.0` is the version this page is pinned to. Check [CLI releases](https://github.com/dorgu-ai/dorgu/releases) for the newest, or use `@latest` to always get it.
</Note>

Ensure `$GOPATH/bin` (or `$HOME/go/bin`) is in your `PATH`.

## From source

```bash
git clone https://github.com/dorgu-ai/dorgu.git
cd dorgu
make build    # builds to ./build/dorgu
make install  # installs to $GOPATH/bin
```

## Verify installation

```bash
dorgu version
```

From a release archive, the commit and build date are stamped in:

```
dorgu version v0.10.0
Build: fb43d86 @ 2026-08-22T22:15:06Z
```

`go install github.com/dorgu-ai/dorgu/cmd/dorgu@...` cannot set those build flags, so it prints `Build: from source` instead. That is a working install, not a broken one. Building from a clone with `make build` or `make install` does stamp the commit and date.
